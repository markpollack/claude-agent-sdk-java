# Claude Agent SDK for Java 1.5.0

A security and packaging release. No public API changed; every 1.4.0 program compiles
and runs unmodified against 1.5.0.

Licensing is unchanged: this SDK is and remains Apache License 2.0.

## Why upgrade

**1.4.0 handed standalone consumers vulnerable Jackson.** If you depend on
`claude-code-sdk` without importing a BOM, 1.4.0 resolves a runtime closure containing
`com.fasterxml.jackson.core` 2.21.2 and `tools.jackson.core` 3.0.3 — 23 known
vulnerabilities, 8 of them HIGH.

The reactor build was clean, which is why this went unnoticed: `flattenMode=ossrh`
strips `<dependencyManagement>` from the published POM, so the parent's Jackson BOM
imports governed the project's own build but never travelled to anyone consuming it.

1.5.0 declares the floors directly on the published module, so they travel. The same
no-BOM consumer now resolves the same 18-artifact closure with **zero** findings.

Nothing makes 1.4.0 safe retroactively. Upgrading is the fix.

## Changes

### Dependencies

- Jackson 2 floor raised to **2.21.6** (from 2.21.2).
- Jackson 3 floor raised to **3.1.6**, declared directly on `claude-code-sdk` rather
  than only imported into the parent's dependency management.
  `tools.jackson.dataformat:jackson-dataformat-yaml` is declared alongside core and
  databind because Jackson 3 requires its modules to share a minor version.
- `org.snakeyaml:snakeyaml-engine` moves 2.10 to 3.0.1 as a consequence, pulled by the
  aligned YAML dataformat.

### Packaging

- The binary, sources and Javadoc archives now each embed the repository's Apache
  License 2.0 text at `META-INF/LICENSE`, byte-identical to the root `LICENSE`.
- A single aggregate **CycloneDX 1.6 JSON SBOM** is produced and published, attached to
  `claude-agent-sdk-parent`. Previously no SBOM was produced at all.
- The parent POM is no longer excluded from the release bundle.
- The published POM resolves from Maven Central only; the unused Spring and Central
  Portal snapshot repositories are gone.

### Build and CI

- `scripts/standalone-consumer-gate.sh` reproduces the no-parent, no-BOM consumer
  shape, asserts the Jackson floors and the Java 21 artifact shape, and runs an offline
  smoke over the resolved closure. It derives the Maven version, so it needs no edit
  across releases. CI runs it on every build.
- CI, snapshot and release workflows are pinned to an immutable build-tools commit, and
  snapshot and release verification no longer skip tests.
- The nightly OWASP-NVD workflow and the `-Powasp` profile are removed in favour of an
  offline local Trivy procedure; `scripts/security-scan.sh` scans the actual consumer
  JAR closure first and the SBOM as supporting inventory.

## Claude Code CLI compatibility

Verified against Claude Code CLI **2.1.235** for the capabilities this SDK already
exposes: executable discovery, process startup, option construction, the control
protocol handshake, recorded-fixture parsing, session identifiers, hooks, permissions,
MCP message handling and clean shutdown.

Flags the CLI has added since 1.4.0 — `--forward-subagent-text`, `--autocompact`,
`--cloud`, `--environment`, `--teleport`, `--safe-mode`, `--bg`/`--background` and
`--ax-screen-reader` — are **not** modelled by `CLIOptions` in this release and are
recorded as future compatibility backlog. Most are cloud, remote-session or interactive
UI concepts with no local-subprocess equivalent. Anything you need today remains
passable through `extraArgs`.

## Compatibility

- Java 21 or later, unchanged.
- No API additions, removals or behaviour changes.
