# Claude Agent SDK Java 1.8.0

Fixes four Jackson vulnerabilities and lets a consumer keep every line the Claude CLI writes to standard
output, exactly as the SDK read it.

## Why this release exists

**Jackson.** Published 1.7.0 declares Jackson 2.22.2 and 3.2.2 at compile scope, and both carry
CVE-2026-89407 and CVE-2026-89425 (jackson-core) and CVE-2026-91776 and CVE-2026-91777 (jackson-databind),
all CVSS 7.5; the Jackson 3 line carries the latter three. A consumer without its own Jackson BOM inherits
them. 1.8.0 declares 2.22.3 and 3.2.3.

**Verbatim lines.** Before this release, only regular messages kept the JSON line they were parsed from.
Control requests, control responses and rate-limit events dropped it; blank lines, message types the SDK does
not know and lines that fail to parse were logged and discarded; and every line was trimmed before parsing. A
consumer recording a session, such as Agent Journal, could not keep what the CLI actually wrote.

## What changed

- Jackson 2.22.2 → 2.22.3 and 3.2.2 → 3.2.3 (`bc89a1da`). The standalone consumer gate's Jackson floors are
  raised to match, so the published shape cannot fall back below the fix.
- `CLIOptions.Builder.rawLineListener(Consumer<String>)` receives each standard-output line exactly as read,
  on the transport's reader thread, before the SDK trims, skips or parses it (`762a4854`, `79df7a4a`). Blank
  lines, unknown message types, malformed lines and the partial last line of a killed process all reach it. A
  line arrives decoded to text with its line terminator removed, otherwise unchanged: character for
  character, not byte for byte. The listener should return quickly; an exception it throws is logged and does
  not stop the stream. Not set, nothing changes.
- `ParsedMessage.rawJson()` returns the original JSON line for every message kind. `Control`,
  `ControlResponseMessage` and `RateLimitEventMessage` now keep it, as `RegularMessage` already did;
  `EndOfStream` returns null, as does a message built in code.

## Upgrading

Bump `io.github.markpollack:claude-code-sdk` to 1.8.0. Code that builds `CLIOptions` with its builder, and
code that creates parsed messages with the `of(...)` factories, needs no change.

One source change: record canonical constructors gained a component. Code that calls `new CLIOptions(...)`
directly passes the new `Consumer<String> rawLineListener` (or `null`) after `includeHookEvents`. Code that
calls the canonical constructor of `ParsedMessage.Control`, `ControlResponseMessage` or
`RateLimitEventMessage`, or deconstructs one of them in a record pattern, adds the `String rawJson`
component. No callers are known outside this repository.
