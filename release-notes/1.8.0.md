# Claude Agent SDK Java 1.8.0

Fixes four Jackson vulnerabilities, lets a consumer keep everything the Claude CLI writes, bounds and reports
session shutdown, and repairs three wire-format defects in setup, control responses and hook responses.

## Why this release exists

**Jackson.** Published 1.7.0 declares Jackson 2.22.2 and 3.2.2 at compile scope, and both carry
CVE-2026-89407 and CVE-2026-89425 (jackson-core) and CVE-2026-91776 and CVE-2026-91777 (jackson-databind),
all CVSS 7.5; the Jackson 3 line carries the latter three. A consumer without its own Jackson BOM inherits
them. 1.8.0 declares 2.22.3 and 3.2.3.

**Recording a session.** Before this release, only regular messages kept the JSON line they were parsed from.
Control requests, control responses and rate-limit events dropped it; blank lines, message types the SDK does
not know and lines that fail to parse were logged and discarded; and every line was trimmed before parsing. A
consumer recording a session, such as Agent Journal, could not keep what the CLI actually wrote, as text or as
bytes.

**Wire defects.** Three paths sent the CLI something other than what the caller configured:

- A requested MCP configuration that could not be serialized or written to its temporary file was logged, and
  the CLI was launched and prompted without it.
- Every control response carried its `subtype` field twice.
- Hook callback responses were rebuilt by hand: `continue` was always sent, even as `null`, and the
  `hookSpecificOutput` decision fields were flattened to top-level snake_case names the CLI does not read. A
  PreToolUse `deny` returned by a hook was therefore not applied by the CLI.

**Shutdown.** `close()` could still outlast its allowance, and a caller had no way to tell whether the CLI and
its descendants had actually exited.

## What changed

### Recording

- Jackson 2.22.2 → 2.22.3 and 3.2.2 → 3.2.3 (`bc89a1da`). The standalone consumer gate's Jackson floors are
  raised to match, so the published shape cannot fall back below the fix.
- `CLIOptions.Builder.rawLineListener(Consumer<String>)` receives each standard-output line exactly as read,
  on the transport's reader thread, before the SDK trims, skips or parses it (`762a4854`, `79df7a4a`). Blank
  lines, unknown message types, malformed lines and the partial last line of a killed process all reach it. A
  line arrives decoded to text with its line terminator removed, otherwise unchanged: character for
  character, not byte for byte. The listener should return quickly; an exception it throws is logged and does
  not stop the stream. Not set, nothing changes.
- `ParsedMessage.rawJson()` returns the original JSON line for every message kind. `Control`,
  `ControlResponseMessage` and `RateLimitEventMessage` now keep it, as `RegularMessage` already did;
  `EndOfStream` returns null, as does a message built in code.
- New `TransportByteObserver`, set with `CLIOptions.Builder.transportByteObserver(...)`, receives the
  original process bytes: stdout and stderr before UTF-8 decoding, stdin after each successful encoded write
  (`a706fc72`). Callbacks run synchronously, in order within each stream; the caller owns the recording. An
  observer failure is retained in the transport's `getSessionError()`. With an observer set, normal
  completion drains both readers before `waitForCompletion` succeeds. Not set, nothing changes. See the
  README section "Observing process bytes".

### Setup and wire format

- A requested MCP configuration that cannot be serialized, created or written now fails with the existing
  `TransportException` before the process starts or any prompt is sent (`f555e72b`). The partial temporary
  file is deleted; a cleanup failure is attached as suppressed. Both clients keep the cause and stay
  disconnected. An empty or healthy configuration behaves as before.
- Control responses emit `subtype` exactly once, on success and on error (`f1d68751`). Constructors, factory
  methods and round-trip deserialization are unchanged.
- Both clients now send a hook callback's `HookOutput` as it is (`2f31aff8`): absent optional fields are
  omitted, and `hookSpecificOutput` keeps its nested camelCase fields (`hookEventName`, `permissionDecision`,
  `permissionDecisionReason`, `updatedInput`, `additionalContext`). A PreToolUse deny is sent as
  `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}`.
  A callback that throws or returns null still blocks, and an unknown callback ID still gets a control error.
  `HookOutput.async()` is documented as a notification, not a way to enforce a permission decision.

### Shutdown

- `close()` makes one bounded cleanup attempt with a seven-second allowance covering the observed process tree,
  reader draining and resource cleanup (`a9a318bd`). It terminates only the process handles it observed,
  gracefully and then forcibly, and checks actual exit. A further call does not renew the allowance. If the
  allowance expires, the transport's `getSessionError()` records it (`bd033eba`).
- New `TransportResourceSnapshot`, from `ClaudeSyncClient.transportResources()`,
  `ClaudeAsyncClient.transportResources()` and `StreamingTransport.resourceSnapshot()`, reports the observed
  processes and their states, each reader's completion and EOF, executor and stream closing and temporary MCP
  file cleanup, including after close. `observedResourcesTerminated()` covers that observed inventory only; it
  is not operating-system containment. Both interface methods are defaults returning empty, so other
  implementations keep compiling. See `docs/transport-cessation.md`.

### Removed

- The public class `io.github.markpollack.claude.agent.sdk.ClaudeCliPrototype` and its live test
  `ClaudeCliPrototypeIT` are removed. The class was an early harness for trying zt-exec against the CLI; no SDK
  code used it. Use `ClaudeSyncClient` or `ClaudeAsyncClient`.

### Build

- Snapshot publication uses build-tools `76a0c8c`, which waits out Central's 429 responses (`7fcad2ee`).
- Two Javadoc errors exposed by release packaging are fixed (`1ad34007`).

## Upgrading

Bump `io.github.markpollack:claude-code-sdk` to 1.8.0. Code that builds `CLIOptions` with its builder, and
code that creates parsed messages with the `of(...)` factories, needs no change.

Source changes, needed only where they apply:

- `CLIOptions`' canonical record constructor gained **two** components: `Consumer<String> rawLineListener`
  after `includeHookEvents`, and `TransportByteObserver transportByteObserver` last, after `safeMode`. Code that
  calls `new CLIOptions(...)` directly or deconstructs it in a record pattern passes both (`null` for none).
- The canonical constructors of `ParsedMessage.Control`, `ControlResponseMessage` and `RateLimitEventMessage`
  gained a `String rawJson` component; direct constructor calls and record patterns add it.
- Code that referenced `ClaudeCliPrototype` moves to `ClaudeSyncClient` or `ClaudeAsyncClient`.

No callers of the changed constructors or of `ClaudeCliPrototype` are known outside this repository.

A hook that returns a `hookSpecificOutput` decision needs no change: the decision now reaches the CLI in the
nested form it reads, where 1.7.0 flattened it. No `continue(true)` workaround is needed.

## Live verification
